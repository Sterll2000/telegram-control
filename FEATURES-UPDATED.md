# Обновлённая логика проверок, AFK и статусов

## Проверки
- Проверку вносит сотрудник с 4–5 звёздами.
- Целевой администратор выбирается только из актуального списка «Админы», который синхронизируется из Iris.
- Для каждой проверки хранятся: сообщения `N/M`, ответы `N/M`, дополнительные показатели, итоговые баллы и замечания.
- Если показатель не идеален (`8/10`, `5/6`, `3/10`), система автоматически формирует блок «Что повторить».
- Если все показатели идеальны, блок замечаний не показывается.
- В статистике каждый администратор отображается отдельной карточкой с последней проверкой и средним результатом.

## Админы
- Для каждого администратора хранится дата постановки на пост `adminSince`.
- В карточке показывается стаж: годы / месяцы / дни и общее число дней.
- Префикс, цвет префикса и статус доступны 4–5 звёздам.

## AFK
- 1–3 звезды создают заявку с датой начала, датой окончания и причиной.
- Заявка получает статус `PENDING`.
- Все 4–5 звёзд видят заявку и могут одобрить/отклонить. Достаточно одного решения.
- После решения пользователь получает уведомление в приложении в разделе «Колокол».
- Дополнительно бот отправляет Telegram-сообщение на `AFK_NOTIFY_TELEGRAM_ID`.

## Iris / бот
- Источник списка админов остаётся Iris.
- Автоматизация использует ровно два чата: BLACK и BLUE.
- Ответ Iris сохраняется в локальную БД, а при наличии Supabase — дополнительно в PostgreSQL.


## Сверка при входе и аватары
- При входе в приложение при включенной автоматизации создаётся запрос на свежую сверку Iris (с защитой от частых повторов).
- Worker `npm run iris:bot` видит запрос, отправляет `кто админ` в ровно два чата (BLACK/BLUE), читает ответ Iris через MTProto и обновляет БД.
- Worker дополнительно получает Telegram-профиль каждого найденного username и сохраняет текущую аватарку в `public/avatars`.
- В списке админов и профиле аватарка показывается с безопасным fallback.
- Кнопка ↻ обновляет страницу, кнопка облака ставит принудительный запрос на сверку.
